# SO101 RTC 人工接管纠正采集

本包在本地 Dell 的 lerobot 环境运行。AutoDL RTC 服务和 18088 SSH 隧道沿用，不修改服务器或已有脚本。先关闭其他控制/遥操作程序，串口和相机仅供本程序使用。

基于用户上传的客户端和数据接口编写。语法、6项控制单元测试、5项自动对齐测试和完整模拟采集流程通过；尚未在真实串口、摄像头、LeRobot数据写入环境中运行。第一次先只采一条确认保存。

## 启动

```bash
conda activate lerobot
cd /home/k/soarm101/lerobot
unzip -n ~/Downloads/pi05_dagger_collect_bundle.zip
python dagger_delivery/pi05_dagger_collect.py --episode 0 --request-after 10 --slew 10 --max-relative-target 20.0
```

若下载到其他位置修改 zip 路径。原脚本默认 slew=10，此命令明确保持10；如果你的固定基线是15，在整批保持同一值并用 --slew 15。默认最大模型运行120秒、人工录制120秒、帧率30。

保持前台交互运行，不使用 nohup。输入场景描述，填方块位置、朝向与起始姿态。连接后从臂保持当前位置，不会立即自动开始；主臂保留原校准 ID。

- A：开始模型控制。按一次即可。
- T：接管。立即使旧动作队列与待处理回复失效，保持从臂当前位置，自动移动主臂靠近该姿态（5归一化单位/秒、30Hz）。自动阶段再次T取消并释放主臂力矩。
- 自动运动时不要阻挡主臂，留出活动空间。粗对齐阈值肘关节4、其余2，最多60秒；完成后主臂力矩释放，手扶主臂微调。六个关节包括夹爪均需差值<=2并稳定0.5秒（归一化位置单位，不是角度）。不要移动从臂或重新摆放失败后的方块。
- R：对齐后开始录制与主臂控制。从此记录人工纠正动作；对齐阶段不录。
- S：完成纠正、抓取和放置后结束录制并保持姿态。
- 退出键盘控制后，输入大写 YES 才保存有效示范；其他回答标记废弃。随后填写实际偏移方向、失败状态和纠正操作。
- Q：停止当前阶段，已有人工帧进入保存询问；无人工帧则废弃。
- Ctrl+C：异常退出，本次标记 interrupted，不纳入训练。

模型或网络出错时，自动停止模型控制并转为保持/对齐阶段，可人工接管；没有自动恢复模型控制。键盘只在主循环轮询，遇硬件阻塞时不能替代硬件停止。

运行前需要存在 my_awesome_leader_arm / my_awesome_follower_arm 校准文件。脚本 connect(calibrate=False)，校准缺失或与硬件不匹配则停止，不发起校准流程。不要手掰带力矩的从臂。

## 录制规则

训练标签是主臂目标经过 slew、关节范围与从臂相对限幅后实际发送的 action。每帧先读从臂观测/双相机，再发人工动作并记录。模型段仅记录状态/动作/请求 JSONL，没有写入训练数据，也不包含连续模型段视频。

首次 R 后的训练观测仍是模型失败处的状态；抬升、张开、对准都应在 R 后由人工完成。若方块位置已被人为改变，此条不能再描述为原失败状态恢复。

输出根目录：
/run/media/k/新加卷/lerobot_datasets/so101_dagger_v1

每次启动只录一条：
- episode_000000/metadata.json：计划编号、train/validation、失败类别、场景、实际频率、状态、服务器与参数。
- episode_000000/rollout.jsonl：模型和人工动作诊断日志。
- episode_000000/dataset/：单条 LeRobot 数据集（内部 episode_index=0）。

根目录是本批采集容器，不是一个已合并的 LeRobot 数据集。采完后按计划编号合并并建立映射，混合旧训练数据。不能将每个子数据集的内部编号0误认为同一条记录。保留验证划分。

先保存到独立子目录是为了避免与现有数据覆盖/混写，也不依赖未经确认的 append/reset 接口。

## 20条计划

方向以黑框在前视画面中的方向描述，并在备注中记录夹爪相对方块实际偏移；不强行制造碰撞。

|编号|用途|类别/数量|起始状态与纠正|
|---|---|---|---|
|0–5|训练|左上角定位偏差6条|模型实际偏离位置；抬离→水平对准→抓取→放置，记录偏移方向与方块朝向|
|6–10|训练|空抓5条|闭爪或半闭但方块未抓起；抬离→张开→对准→再抓→放置|
|11–15|训练|固定爪接触/将顶住5条|及时接管；抬离→张开→调整位置与腕角→抓取→放置|
|16–17|验证|左上角定位偏差2条|独立rollout，不同精确位置/朝向；完整人工纠正|
|18|验证|空抓1条|独立rollout；完整人工纠正|
|19|验证|固定爪接触/将顶住1条|独立rollout；完整人工纠正|

验证场景提前选定，不按模型表现好坏重分训练/验证。类别记录须与现场实际情况一致。没有发生计划失败就取消该条，稍后重新尝试，不把正常成功段冒充纠错段。

## 检查与重录

```bash
python dagger_delivery/check_collection.py
```

状态 accepted 且 total_episodes=1 才可合并；timing_review 表示已保存但实际平均频率<27Hz、帧间隔>0.2秒或少于30帧，需要检查，不自动加入训练。这是本采集器的保守检查门槛，不是 LeRobot 标准。相机/磁盘写入导致频率不足时先解决，不把慢数据直接标成正常30Hz使用。

成功后以 --episode 1 运行下一条。失败后重新录同一编号：

```bash
python dagger_delivery/pi05_dagger_collect.py --episode 0 --retry --request-after 10 --slew 10 --max-relative-target 20.0
```

--retry 将未通过确认的旧尝试移入 rejected_attempts，保留原文件；拒绝覆盖 accepted。失败例子也应保留供分析。程序崩溃留下的数据不自动采纳。主臂自动对齐正常结束、取消、超时或异常均尝试释放力矩，Ctrl+C走相同清理流程；串口故障导致释放失败时会提示硬件停止。

保持从臂力矩后若要复位，退出本程序再启动原遥操作工具；不能同时打开两套控制。下一条的主臂对齐始终在 T 后进行。

## 延迟策略

保留实际过时回复检查和队列不足检查。首次 bootstrap 是静止等待，不把其可能的冷启动耗时加入稳态延迟历史；后续 guided 请求仍使用最近20次最大延迟加2步、且不小于 initial-delay。request-after 默认10。延迟超预算时转人工接管，不强行缩小估计继续执行旧动作。
